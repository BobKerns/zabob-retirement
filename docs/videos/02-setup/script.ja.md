## Scene `title`: タイトル

シミュレーターで考える老後の資金計画。第2回、セットアップとインストールです。

この回では、アリスが自分のコンピューターにシミュレーターを入れて、家計のデータを入れるフォルダーを作ります。最後には、プランを実行できるようになり、どの実行もあとで正確に再現できるようになります。

## Scene `uv`: まず uv

シミュレーターは、{uv|ユーブイ}という道具で入れます。{uv|ユーブイ}は、シミュレーターに合ったパイソンも用意してくれます。マック、リナックス、またはウィンドウズのダブリューエスエルでターミナルを開きます。{uv|ユーブイ}がまだなければ、{uv|ユーブイ}のウェブサイトにあるこの1行で入れて、新しいターミナルウィンドウを開いてください。ウィンドウズでは、先にダブリューエスエルを準備してください。その短い動画へのリンクは、セットアップガイドへのリンクと一緒に、説明欄にあります。

## Scene `install`: シミュレーターを入れる

あとは1行で、シミュレーターが入ります。{uv|ユーブイ}が、シミュレーターと必要なものすべてをダウンロードして専用の場所に置き、{sim|シム}と{analysis|アナリシス}のコマンドを、ターミナルから使えるようにします。初回は1、2分かかることがあります。ギットの知識も、コードの管理方法の知識もいりません。

## Scene `terminals`: 画像を表示できるターミナル

```slide
heading = "画像を表示できるターミナル"
body = [
  "マック: iTerm2 または Ghostty",
  "リナックス: kitty、Ghostty または WezTerm",
  "どこでも: VS Code のターミナル",
  "それ以外では、グラフを画像ファイルに保存",

```

シミュレーターは、どのターミナルでも動きます。ただ、いくつかのコマンドはターミナルの中にグラフを描けるので、そのためには画像を表示できるターミナルが向いています。マックなら、アイターム・ツーかゴースティー。リナックスなら、キティ、ゴースティー、またはウェズターム。どこでも使えるのは、ブイエスコードの内蔵ターミナルで、設定で画像表示をオンにします。それ以外のターミナルでは、グラフは画像ファイルに保存され、コマンドがその場所を教えてくれます。一覧はセットアップガイドにあります。

## Scene `two-folders`: プログラムと、あなたのデータ

```slide
heading = "プログラムと、あなたのデータ"
body = [
  "プログラム: uv が管理。アップグレードしてもデータには触れません。",
  "ホームフォルダーの zabob-retirement: あなたの家計。履歴つきのテキストファイルです。",
]
```

こうして、二つの部分ができます。プログラム、つまりシミュレーターそのものは、{uv|ユーブイ}が目立たない場所で管理します。あなたのデータ、つまり家計、口座、プランは、専用のフォルダーに入ります。この二つは、わざと分けてあります。プログラムをアップグレードしても数字には触れませんし、数字があなたのコンピューターの外に出ることもありません。データフォルダーは自分の履歴を持つので、どの実行も、どのバージョンのデータとプログラムから生まれたのかを正確に記録できます。

## Scene `init`: データフォルダーを作る

{sim init|シム・イニット}は、データフォルダーを作ります。ほかの場所を指定しなければ、ホームフォルダーの{zabob-retirement|ザボブ・リタイアメント}です。まず、あなたが誰かを尋ねます。データの中であなたを表す、一語のアイディー。名前。生年月日は、メディケアや最低引き出し額などに関わる年齢を決めます。性別は、寿命をばらつかせたいときに生命表を選ぶためのもので、空欄でもかまいません。そして世帯の税の申告区分で、夫婦合算申告が既定です。それからフォルダーを作り、最初のシナリオ、ベースが読み込めることを確かめ、ノートブックをコピーし、ギットですべての最初のバージョンを保存します。マックで、ギットを含むコマンドラインツールを入れるか尋ねるウィンドウが出たら、インストールを終えてから、もう一度{sim init|シム・イニット}を実行してください。

## Scene `inside`: 中身

中にはフォルダーが二つあります。{notebooks|ノートブックス}にはノートブックが入っていて、あとで紹介します。{sim|シム}にはデータが入っています。テキストファイルで、ほとんどはどの表計算ソフトでも開ける表です。{persons|パーソンズ}には世帯の人が入ります。{scenarios|シナリオズ}にはプランが入り、最初はベースです。ベースには家計そのもの、つまり口座、収入、支出、そしてお金を動かすルールを書きます。今はまだほとんど空で、次の回で埋めていきます。税の表などの標準的な前提は、ここにはコピーされません。プログラムから読み込まれるので、アップグレードすれば最新のままです。

## Scene `activate`: データを有効にする

新しいターミナルウィンドウを開くたびに、この1行でデータを有効にします。{sim|シム}コマンドにデータの場所を教え、プロンプトにそれを表示します。データ、あなた、そして現在のシナリオ、ベースです。ほとんどのコマンドは、別のシナリオを指定しない限り、現在のシナリオに対して働きます。{sim switch|シム・スイッチ}は、どれが現在のシナリオかを教えてくれます。

## Scene `plan`: 自分のプラン

新しいシナリオは、別のシナリオの上に作ります。{sim scenario create|シム・シナリオ・クリエイト}で、ベースの上に{my plan|マイ・プラン}を作り、それを現在のシナリオにします。プロンプトもそれに合わせて変わります。まだ自分の中身がないので、今はベースと同じです。{sim switch|シム・スイッチ}にシナリオの名前を付けると、現在のシナリオを元に戻せます。ほかのコマンドでシナリオの名前を指定しても同じです。

## Scene `notebooks`: ノートブック

  "データフォルダーの notebooks に入っています",

ターミナルのほかに、シミュレーターにはジュピターノートブックが付いています。メニューやスライダーで見ていく、グラフと表のページで、コードを書く必要はありません。{sim init|シム・イニット}が、データフォルダーに入れてくれました。開くには、有効にしたターミナルで{analysis jupyter|アナリシス・ジュピター}と入力します。ウェブブラウザーにジュピターラボが開き、左側にノートブックが並びます。第4回で一つずつ紹介します。

## Scene `commit`: 作業を保存する

コマンドでもファイルの編集でも、データを変えると、その変更はまだどこにも記録されていません。そうした変更があるままシナリオを実行すると、{sim run|シム・ラン}は変更を一覧にして、先にバージョンを保存するか尋ねます。既定のはいを選ぶと、何が変わったかを書いたメッセージを付けて保存し、それから実行します。これで実行を再現できるようになります。実行は、読み込んだ保存済みのバージョンを記録するので、あなたも、共有した相手も、あとで同じ答えを得られますし、二つの実行の間で何が変わったかも分かります。{sim init|シム・イニット}はバックグラウンドビルドもオンにしたので、変更を保存すると、影響を受けるシナリオがすべて裏で実行し直されます。実行せずに保存だけしたいときは、{sim commit|シム・コミット}を使います。

## Scene `upgrade`: アップグレード

```slide
heading = "アップグレード"
body = [
  "uv tool upgrade zabob-retirement",
  "次に新しいノートブック: sim notebooks copy --replace",
  "古いバージョンで作った実行は、作り直されます",
]
```

あとでシミュレーターをアップグレードするには、{uv tool upgrade|ユーブイ・ツール・アップグレード}に名前を付けて実行します。それから、{sim notebooks copy|シム・ノートブックス・コピー}に{--replace|リプレース}を付けて、新しいノートブックをデータフォルダーに入れます。手元のコピーは置き換わるので、自分で変えたノートブックは、先に別の名前で保存しておいてください。古いバージョンで作った実行は古くなり、新しいバージョンで作り直されます。
